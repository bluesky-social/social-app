## SurfaceMountingManager.kt Patch - addViewAt crash for views held by startViewTransition

On Android, a view stays attached to its old parent after Fabric removes it if
that parent called `ViewGroup.startViewTransition(view)` first (AOSP keeps
`mParent` for views in `mTransitioningViews`). react-native-screens does this
for every view in a screen it is animating out. If Fabric then inserts the same
view somewhere else, `addViewAt`'s fallback `removeView` does nothing, because
the old parent no longer lists the view as a child, and `addView` throws "The
specified child already has a parent". This is Sentry APP-T2K4 (Linear
APP-3492). With native view recycling on (APP-3835), a pooled view that was
still held this way crashes the same way when it is reused.

Backport of https://github.com/react/react-native/pull/59776. When the view's
parent no longer lists it as a child, `addViewAt` calls `endViewTransition` on
that parent before inserting the view. It landed on `main` on November 4, 2026
as commit `45152f1f853541d8db3a24f34ff439ebf9b388b6` and was cherry-picked to
0.89-stable, but not to 0.88-stable.
