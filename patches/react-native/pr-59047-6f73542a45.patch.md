## BaseViewManager.java / ReactAccessibilityDelegate.kt / ReactTextView.java / ReactViewGroup.kt Patch - recycled Android views keep accessibility state

We turn on Fabric's native view recycling on Android (`enableViewRecycling`,
set in `plugins/withAndroidPreparedTextLayoutPlugin.js`). It pools host views
by component type, so a view that leaves the screen can be reused for a later
mount of the same type. In 0.88.1, `BaseViewManager.prepareToRecycleView` does
not reset the accessibility state that props applied to the view itself, so a
reused view can keep its content description, `importantForAccessibility`,
selected state, live region, `screenReaderFocusable`, role and collection tags,
and the accessibility actions its delegate cached. TalkBack can then read the
previous row's label, or skip content that should be visible to it.

Backport of https://github.com/react/react-native/pull/59047. It resets that
state when a view is recycled, clears the delegate's cached actions, stops the
delegate holding on to the view it is labelled by, restores `ReactTextView`'s
`importantForAccessibility`, and clears `ReactViewGroup`'s accessibility order.
It landed on `main` on October 16, 2026 as commit
`6f73542a454fd34d1983cbe8734f86cd09215258` and is on 0.89-stable, but not on
0.88-stable. Every identifier and resource id the backport uses exists in
0.88.1.

Like every React Native Android patch, this only applies to builds that compile
React Native from source (production builds).
