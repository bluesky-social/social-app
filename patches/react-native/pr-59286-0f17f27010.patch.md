## ReactScrollView.kt Patch - Taps in a list stop working after a fling on Android

Backport of https://github.com/react/react-native/pull/59286: the Android
scroll views (`ReactScrollView`, `ReactHorizontalScrollView` and
`ReactNestedScrollView`) finish a drag on `ACTION_CANCEL` the same way they
do on `ACTION_UP`.

Without it, every tap inside the Home feed can be swallowed until the user
scrolls again:

1. A fling makes the scroll view emit `onMomentumScrollBegin`.
2. A touch that stops the fling cancels the pending runnable that would emit
   `onMomentumScrollEnd` (`cancelPostTouchScrolling()` on `ACTION_DOWN`).
3. If that touch ends in `ACTION_CANCEL` instead of `ACTION_UP`, the scroll
   view never finishes the drag, so no new momentum begin/end pair is sent.
   The feed's pager (react-native-pager-view 9, Compose) does this when the
   stop-touch drifts sideways. Gesture handlers and system touch
   cancellation can do the same.
4. JS `ScrollView._isAnimating()` compares the last momentum begin and end
   times, so it stays `true`. `_handleStartShouldSetResponderCapture` then
   captures every touch start, and no Pressable inside the list ever becomes
   the responder.

Only a vertical drag and release, which emits a new begin/end pair, makes
taps work again. That matches the reports: Like and Repost do nothing until
you scroll a few pixels. Reproduced on an Android emulator with adb input:
after a fling, a stop-touch that the pager took left 3/3 runs with every
later tap captured by the scroll view.

Related upstream report: https://github.com/react/react-native/issues/26046.

The PR merged on October 22, 2026 as commit
`0f17f270103950c5a63c9e7e05fb1958e61e419c`. It is in 0.89.0-rc.0 but not in
any 0.88 release. Upstream also regenerated the `@generated` signature of
`ReactNestedScrollView.kt`, which this patch leaves alone.
